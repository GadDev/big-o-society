# Releasing

This project uses [Changesets](https://github.com/changesets/changesets) to version and release from `main`. The package is `private: true` and is never published to npm — a "release" here means a version bump, a `CHANGELOG.md` entry, and a git tag / GitHub Release.

## 1. Record a change

Whenever you make a change worth tracking (new exercise, behavior fix, breaking change to the runner scripts), add a changeset before merging:

```bash
npx changeset
```

You'll be asked:

- **Bump type** — `patch` for fixes/small additions, `minor` for new exercise tracks or non-breaking features, `major` for breaking changes (rare in this repo).
- **Summary** — one or two sentences, written for the changelog reader, not the diff.

This writes a markdown file under `.changeset/`. Commit it along with your change.

## 2. Merge to `main`

Push your branch and merge the PR as usual. No manual version bump is needed — that's automated.

## 3. Automated release (`.github/workflows/release.yml`)

On every push to `main`, the `Release` GitHub Action:

1. Installs dependencies and runs `npm run test:run`.
2. Runs `changesets/action`, which:
   - If there are pending changesets, opens/updates a **"Version Packages"** pull request that bumps `package.json` and rewrites `CHANGELOG.md` from the pending changeset files (via `npm run version`, i.e. `changeset version`).
   - When that PR is merged, creates a git tag for the new version (via `npx changeset tag`) and a corresponding GitHub Release with the changelog entry.

No npm publish step runs — nothing is pushed to a registry.

## 4. Manual equivalent (if you ever need it locally)

```bash
npx changeset version   # bump package.json + CHANGELOG.md from pending changesets
npx changeset tag       # create the git tag for the new version
git push --follow-tags
```

## Notes

- Don't hand-edit `CHANGELOG.md` — it's regenerated by `changeset version` from the `.changeset/*.md` files.
- If a PR doesn't need a release note (docs typo, CI tweak), it can skip adding a changeset — use `npx changeset --empty` if you want a no-op changeset to satisfy a "changeset required" check, though this repo doesn't currently enforce one.
